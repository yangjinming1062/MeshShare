# MeshShare 产品设计

## 体验目标

桌面程序常驻运行，让用户在不同系统的电脑之间继续使用刚复制的内容。Android App 在需要传资料时打开，关闭后不保持节点连接。其他设备的浏览器作为网页端，通过节点地址临时加入，由用户主动操作剪贴板。传文件时，收发两端同时在线，保存位置由接收方决定。

## 操作反馈

设置保存、剪贴板操作、连接和传输结果用底部短暂提示反馈：提示自动消失，也可以点击关闭；新提示直接替换上一条并重新计时，同一条提示连续出现时按最后一次重新计时。窗口在后台时系统会延后定时器，回到前台按剩余时间重排，不会留下已经过期的提示。

提示只表达单次操作的结果。耗时较长的步骤（例如发送前的文件摘要）改用传输列表里的准备行，避免提示长期停留在界面底部。

## 桌面端

主窗口显示当前管理节点和在线设备。设备按行列出，每行左侧是设备类型、名称、平台与地址，右侧是对端实时硬件摘要（CPU、内存、GPU 和上下行速率）；连接断开后对应设备从列表移除。点击设备图标或名称进入该节点，主窗口顶部显示目标名称和「远程管理」标记，返回按钮直接回到本机。远端硬件详情按系统、内存、网络、磁盘和 GPU 分区显示采集到的完整快照，包括 CPU 型号/核心数/频率、交换分区、系统负载、运行时间、各磁盘容量和可用空间，以及 GPU 显存类型和不可用原因；不支持或暂未采集的字段显示占位状态，过期快照不会继续展示旧值。远程目标只有一层：在目标页面中进入其他设备会替换当前目标，不累计返回层级；目标设备列表中列出的本机节点与返回按钮等价，点击即回到本机。硬件摘要仍用于打开硬件详情，发送和文件夹按钮保持原行为。窗口本身不滚动，设备较多时只有设备列表内部滚动。关闭主窗口只隐藏窗口，Windows 下左键双击系统托盘图标也会在显示和隐藏主窗口之间切换，其他桌面平台继续通过托盘菜单操作，托盘的「退出程序」会停止节点。设备名称取对端节点自身配置的名称；缺少可用名称时不使用系统占位主机名，Android 节点显示「移动设备」，桌面节点显示「MeshShare 节点」。

进入远程节点后，剪贴板、历史、设备、硬件、传输、移动访问和设置都从目标节点读取，写操作也在目标节点执行。目标离线时显示重连状态，返回本机不受影响。远程接收文件时，人工确认使用目标机器上的绝对路径或目标节点已配置的默认目录；本机目录选择器不会被解释为远程目录。目标节点重启或安装更新后，界面自动恢复连接。

正式桌面安装包默认开启开机自启动。用户登录系统后，MeshShare 以后台托盘模式启动，节点服务、剪贴板同步和托盘继续运行，主窗口保持隐藏；用户从托盘打开主窗口后，可通过「开机自启动」开关关闭或恢复该行为。普通手动启动仍显示主窗口；重复打开应用只激活已有窗口。自启动不会改变硬件监控偏好，监控悬浮条继续按已保存的可见性运行。

「客户端自动更新」默认每周检查 GitHub 稳定版 Release，也可切换为每天或关闭。发现新版本后，客户端在没有进行中的桌面或网页端文件传输时自动下载、安装并重启；传输进行中会显示等待状态并在任务完成后继续。下载完成进入安装窗口后，新的传输请求会提示稍后重试，已有任务不会被中断。更新检查、下载和安装由后台服务执行，主窗口隐藏在托盘时仍然有效。Linux 以 `.deb` 或 `.rpm` 安装时，安装会请求系统授权并在本机弹出确认对话框；取消授权、没有授权代理或没有 polkit 时显示「待安装 vX」并稍后重试，不计为更新失败，点「立即检查」可立即重新请求。AppImage 直接替换自身文件，不需要授权；首次运行前要给它执行权限，并且与系统包版本共用单实例，系统包版本正在运行时启动 AppImage 只会激活已有窗口。网络错误、清单缺少当前平台、签名校验失败或系统包安装失败时，节点继续运行并显示原因；网络错误保留底层原因，例如域名解析失败、连接失败或超时。本机可以设置更新代理，留空时跟随系统或环境代理；代理只用于检查更新和下载安装包，不改变局域网连接，也不在远程管理界面显示。用户可以点击「立即检查」执行一次检查；关闭频率只关闭后台检查和自动安装，手动检查得到的已是最新或失败原因会继续显示。

「共享剪贴板」显示最新的文字或图片，并提供本机历史列表。桌面复制后自动发布，也可以编辑文字并选择「立即同步当前文字」。历史记录按内容去重，文字和 PNG 图片都保留；桌面端可选择按最近条数或最近天数保存，默认分别为 50 条和 30 天，范围为 1–500 条和 1–365 天。点击历史条目先预览，当前与历史中的图片都按原始比例缩放显示，可点击放大查看；选择「恢复并同步」后才写入本机系统剪贴板并广播新事件；也可以清空本机历史。文字和 PNG 图片单项上限均为 16 MiB。暂停同步会阻止本机采集和主动发布，其他节点仍可更新本机剪贴板。

自动发现依赖局域网组播。主窗口提供「手动输入节点地址」，HTTP 查询成功后会启动带心跳和重试的 WebSocket 连接。远程管理复用目标节点公布的受信任地址和 WebSocket，能力不完整的旧节点提示升级。

## Android App

Android App 打开后启动本机节点，使用局域网 HTTP/WebSocket 与桌面节点通信。App 保存最近成功连接的地址，下一次打开时可直接点选；也可以通过 mDNS 发现或手动输入地址，不要求扫码、配对或安装本地 CA。开启普通全隧道 VPN 时，只要 Wi‑Fi 或以太网仍可用，App 会优先使用物理局域网保持设备发现和连接；Tailscale 组网继续使用 Tailscale 网络。VPN 切换期间节点会自动重建网络监听。关闭 App 后停止节点和传输连接。

Android App 的设备列表可以查看桌面节点的 CPU、内存、GPU、显存和网络摘要，并在硬件详情中查看对端快照。本机只显示网络上传和下载速率，不采集 GPU 或桌面硬件。文件发送使用 Android 文件选择器，接收文件默认保存到应用专属的 Download/MeshShare 目录；任务仍由目标节点校验清单、大小和 SHA-256。

Android App 与网页端共用一套按视口宽度排布的移动版式。顶部固定显示节点名称和连接状态并避开系统状态栏；待确认的接收请求固定在首页顶部，向下滚动时保持可见。每台设备在自己的卡片内提供发送入口，手机宽度只提供文件发送，文件夹发送保留在较宽的浏览器页面。本机网络以紧凑速率显示在页面底部。

正式 Android App 在前台首次检查 GitHub 稳定版，之后默认每周检查。「应用更新」可改为每天或关闭，也可立即检查。新版默认在非计费网络下载，使用计费网络时可手动选择「使用流量下载」。下载或安装开始前会等待收发任务结束。首次自更新时按提示允许 MeshShare 安装应用，系统要求确认时显示 Android 安装界面。取消安装后可以从 App 内继续安装，成功后再次打开即进入新版。

Android App 不自动读取或写回系统剪贴板。打开 App 后，用户可以手动读取本机剪贴板、编辑共享文字、发布到在线节点，也可以把共享文字写回本机剪贴板；这些操作需要用户主动点击。

## 浏览器网页

桌面端在「在线设备」标题栏的「浏览器访问」中用 IP 显示可用的局域网和 Tailscale 地址，排除本机回环地址。选择对端设备能访问的地址后，二维码与 HTTP 地址随之更新；网页端在浏览器打开该地址即可加入，手机也可以扫码。网络接入、断开或换址时列表会自动更新。没有可用地址时，窗口提示先连接网络。

需要选择本地目录并直接写入时，桌面端点「下载本节点 CA 证书」后由系统保存对话框选择位置；保存完成会显示实际路径，并按当前系统给出安装步骤。MeshShare 不自动把 CA 写入系统信任库：本地 CA 私钥以明文保存在节点数据目录，自动安装等于把「能读该文件」扩大成「能为本机信任的任意站点签发证书」。

网页显示连接的桌面节点、在线设备、最新共享文字和接入节点的本机剪贴板历史。用户可以编辑文字并点「同步到设备」，也可以先预览历史再显式恢复并同步；网页端只读查看保留设置，不能修改接入节点的历史策略。系统剪贴板按钮需要浏览器权限和安全上下文，默认 HTTP 页面可通过文本框手动复制粘贴。[Clipboard API 规范](https://w3c.github.io/clipboard-apis/#async-clipboard-api)

页面按视口宽度自适应：窄屏单列，平板与电脑浏览器双列。存在待确认的接收请求时，它固定显示在页面顶部并在滚动时保持可见；接收后任务转入传输记录。接入方式、接收目录选择与 HTTP 安全提示集中在页面底部。

## 文件传输

桌面流程设计为从目标设备卡片选择文件或文件夹，也可将项目拖到卡片上。选定后先由发送端逐项计算 SHA-256 摘要，再向接收端登记任务；摘要期间「传输任务」显示准备行，包含目标、项目数和按字节计算的进度，可随时取消；摘要结束或取消后准备行立即收起。准备行还没有在节点上登记，取消后不会产生任务，也不用通知对端。每个节点在「文件接收行为」中选择「每次确认」或「自动接收」。人工模式下，接收端在「传输任务」（网页端为页面顶部的待接收卡片）中选择「接收」或「拒绝」并选择保存目录；自动模式使用已配置的默认目录，目录不可用时回退到人工确认。普通节点传输由发送方直接上传到接收端；远程管理页面发送时由当前接入节点流式转发。远程管理界面确认接收时输入目标节点路径，目录存在性和安全校验由目标节点完成。

网页端提供向其他在线桌面节点发送文件和文件夹的入口，也会把接入节点列为目标。打开页面后网页端会建立临时接收会话；桌面端可在本机的网页会话卡片中发送文件。HTTP 页面无需安装证书即可接收，点「接收并下载」后文件自动保存到浏览器默认下载位置，节点在下载流完整写出后逐项确认。需要选择本地目录、保留目录结构并直接写入时，用户可安装接入节点提供的本地 CA，再打开 HTTPS 页面。浏览器需要能直接访问接入节点。

当前使用限制如下。

- **桌面接收确认。** 收件任务由 Rust 运行时保留，界面通过 WebSocket 或 `GET /api/v1/transfers` 恢复；接收目录由本机 Tauri 文件选择器确认。自动接收只对新任务生效。macOS 会把本机选择的目录授权保存为 security-scoped bookmark，应用重启后恢复访问，目录被移动或失效时仍回退到人工确认。
- **远程管理。** 目标节点通过 `GET/PATCH /api/v1/settings` 提供设置快照和写操作；`POST /api/v1/transfers/{id}/accept` 接受目标机路径。开机自启、自动更新和监控能力由目标操作系统决定，Wayland 的点击穿透等限制会原样返回。
- **远程文件发送。** 管理端选择的文件通过目标节点的中继接口流式发送给目标节点的在线设备，文件数据会经过当前接入节点，但不写入中央仓库或长期中转存储。目标节点拥有任务状态并沿用普通传输的接受、进度、取消和失败恢复语义；普通桌面/Android 节点之间仍是直接传输。
- **网页端发文件。** 网页端使用分块 SHA-256 实现和 `File.stream()`，不依赖 Web Crypto 安全上下文，也不会一次性读取整个文件。
- **网页接收文件。** 网页接收会话只在接入节点上有效。HTTP 页面在接收后会逐项触发浏览器默认下载，文件夹按文件下载。下载中断时可以重新下载，已提供的项目在「最近下载」中短时保留。HTTPS 页面在完成 CA 信任且浏览器支持 `showDirectoryPicker` 时，可以选择目录、逐项校验并流式写入，成功保存后确认。网页端可以在上传或下载前取消任务，会话空闲 90 秒后任务和临时文件由后台清理，节点启动时会清理上次遗留目录。传输内容和项目数没有固定业务上限，暂存空间受实际磁盘容量约束。
- **传输失败。** 接收端遇到同名文件时拒绝写入，文件校验失败时任务标记为失败。桌面端上传临时文件登记在节点数据目录，流式请求报错、取消或异常退出时清理临时文件；网页端暂存文件在上传失败、任务终止或会话过期时清理，节点启动后也会清理仍登记的遗留文件。界面只把待确认和活动任务放在主列表，完成、拒绝和主动取消的任务不继续堆积；失败任务单独保留最近 20 条且最长 24 小时，显示失败原因；移除会删除节点上的失败记录，之后刷新或重新进入页面都不会再出现。桌面端和网页端上传按已完成项目自动重试，桌面端在连接短暂中断时保持任务活动并按项目退避重试，连续失败后标记为 `failed`；当前页面仍持有源文件时可以递增重试代次继续原任务，已提交项目不会被覆盖，接收目录失效时要求重新确认。活动传输长时间没有进展也会自动失败并清理。全部文件下载后任务进入 `completed`。目标暂时离线时，发送端重试查询进度；对端公布多个地址时在有限探测预算内按顺序尝试，预算耗尽仍提示连接失败。

## 硬件监控

首次启动默认在主显示器右下角显示紧凑的半透明本机硬件监控悬浮条，分两行显示 CPU、GPU、上传速率与内存、显存、下载速率。悬浮条不显示品牌或关闭按钮，未锁定时可以拖动，右键菜单可锁定或隐藏悬浮条；位置会保存并在下次启动恢复。锁定后悬浮条忽略鼠标事件并允许点击穿透。托盘菜单和主窗口「本机硬件」面板都提供锁定开关与显示开关，按当前状态切换文案，隐藏和锁定状态都会保存并在下次启动恢复。隐藏主窗口时，已显示的悬浮条仍可见。隐藏悬浮条后，后台采集和局域网指标共享仍会继续。

在线设备行右侧显示对端的 CPU、内存、GPU 和上下行速率摘要。点击该摘要可查看 CPU/内存/交换分区、网络、磁盘和逐 GPU 的利用率与显存详情，并显示采样时间。显存统计只包含独立显存，共享内存和统一内存不折算；没有独立显存的核显显示为空。多显卡时每张卡单独显示一行。远端快照过期时动态数值显示「—」，等待新快照后恢复；GPU、显存、负载和磁盘信息能否读取取决于平台及驱动。

## 使用边界

- **网络信任。** 节点服务面向受信任网络，可达设备无需账号或配对即可访问共享内容。服务只绑定回环、私网、链路本地和 Tailscale 组网地址，并只公布成功监听且仍有效的地址；手动连接也限制在这些地址，公网地址不会被监听或放入二维码。HTTP 网页模式不提供链路加密、完整性保护或同网设备认证，只适合受信任网络；HTTPS+CA 只用于保护浏览器到节点的链路，不改变节点无账号的访问边界。
- **数据保留。** 每台机器独立持久化剪贴板历史和当前快照；历史按配置的条数或天数淘汰，相同内容只保留一条，文字和 PNG 图片单项均不超过 16 MiB，历史 payload 总量默认不超过 512 MiB，达到上限时优先清理最旧记录。历史不会通过节点间 WebSocket 批量同步。硬件指标只保留最新快照，传输任务状态随节点运行保存在内存。发送端的文件内容仍由窗口选出的 `File` 对象提供，窗口关闭前未上传完的文件需要重新选择。网页暂存文件在项目完成、取消、失败或会话过期后清理。
- **Wayland 桌面。** 系统剪贴板优先使用合成器提供的原生 data-control 协议，没有该协议时回退到 XWayland；两条通道都不可用时，桌面界面会显示原因并持续重试。此时在「共享剪贴板」中输入文字仍会写入 MeshShare 历史并广播给其他节点，只是无法写入本机系统剪贴板。Wayland 下悬浮监控条仍可显示和拖动，但全局坐标、强制置顶和点击穿透由合成器决定，不作为强保证。
