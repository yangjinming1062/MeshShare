# MeshShare 产品设计

## 体验目标

桌面程序常驻运行，让用户在不同系统的电脑之间继续使用刚复制的内容。手机和平板通过浏览器临时加入，由用户主动操作剪贴板。传文件时，收发两端同时在线，保存位置由接收方决定。

## 桌面端

主窗口显示当前节点和在线设备。设备按行列出，每行左侧是设备类型、名称、平台与地址，右侧是对端实时硬件摘要（CPU、内存、GPU 和上下行速率）；连接断开后对应设备从列表移除。窗口本身不滚动，设备较多时只有设备列表内部滚动。关闭主窗口只隐藏窗口，托盘的「退出程序」会停止节点。

正式桌面安装包默认开启开机自启动。用户登录系统后，MeshShare 以后台托盘模式启动，节点服务、剪贴板同步和托盘继续运行，主窗口保持隐藏；用户从托盘打开主窗口后，可通过「开机自启动」开关关闭或恢复该行为。普通手动启动仍显示主窗口；重复打开应用只激活已有窗口。自启动不会改变硬件监控偏好，监控悬浮条继续按已保存的可见性运行。

「客户端自动更新」默认每周检查 GitHub 稳定版 Release，也可切换为每天或关闭。发现新版本后，客户端在没有进行中的桌面或手机文件传输时自动下载、安装并重启；传输进行中会显示等待状态并在任务完成后继续。下载完成进入安装窗口后，新的传输请求会提示稍后重试，已有任务不会被中断。更新检查、下载和安装由后台服务执行，主窗口隐藏在托盘时仍然有效。网络错误、清单缺少当前平台或签名校验失败时，节点继续运行并显示更新失败原因。用户可以点击「立即检查」执行一次检查；关闭频率只关闭后台检查和自动安装。

「共享剪贴板」显示最新的文字或图片，并提供本机历史列表。桌面复制后自动发布，也可以编辑文字并选择「立即同步当前文字」。历史记录按内容去重，文字和 PNG 图片都保留；桌面端可选择按最近条数或最近天数保存，默认分别为 50 条和 30 天，范围为 1–500 条和 1–365 天。点击历史条目先预览，选择「恢复并同步」后才写入本机系统剪贴板并广播新事件；也可以清空本机历史。文字和 PNG 图片单项上限均为 16 MiB。暂停同步会阻止本机采集和主动发布，其他节点仍可更新本机剪贴板。

自动发现依赖局域网组播。主窗口提供「手动输入节点地址」，HTTP 查询成功后会启动带心跳和重试的 WebSocket 连接。

## 手机和平板网页

桌面端在「在线设备」标题栏的「手机访问」中用 IP 显示可用的局域网和 Tailscale 地址，排除本机回环地址。选择移动设备能访问的地址后，二维码随之更新。网络接入、断开或换址时列表会自动更新。没有可用地址时，窗口提示先连接网络。

网页显示连接的桌面节点、在线设备、最新共享文字和扫码节点的本机剪贴板历史。用户可以编辑文字并点「同步到设备」，也可以先预览历史再显式恢复并同步；手机网页只读查看保留设置，不能修改扫码节点的历史策略。系统剪贴板按钮需要浏览器权限和安全上下文，默认 HTTP 页面可通过文本框手动复制粘贴。[Clipboard API 规范](https://w3c.github.io/clipboard-apis/#async-clipboard-api)

## 文件直传

桌面流程设计为从目标设备卡片选择文件或文件夹，也可将项目拖到卡片上。每个节点在「文件接收行为」中选择「每次确认」或「自动接收」。人工模式下，接收端在「传输任务」中选择「接收」或「拒绝」并选择保存目录；自动模式使用已配置的默认目录，目录不可用时回退到人工确认。文件内容由发送方直接上传到接收端。

移动网页提供向其他在线桌面节点发送文件和文件夹的入口，也会把扫码连接的桌面节点列为目标。扫码后手机会建立临时接收会话；桌面端可在本机的移动设备卡片中发送文件。手机首次接收时先安装扫码节点提供的本地 CA，在 HTTPS 页面选择存储目录并确认，随后逐项流式写入该目录。浏览器需要能直接访问扫码节点。

当前使用限制如下。

- **桌面接收确认。** 收件任务由 Rust 运行时保留，界面通过 WebSocket 或 `GET /api/v1/transfers` 恢复；接收目录由本机 Tauri 文件选择器确认。自动接收只对新任务生效。
- **手机在默认 HTTP 页面发文件。** 手机网页使用分块 SHA-256 实现和 `File.stream()`，不依赖 Web Crypto 安全上下文，也不会一次性读取整个文件。
- **手机接收文件。** 手机接收会话只在扫码节点上有效，文件由该节点临时保存并通过 HTTPS 流下载；手机先选择目录，再逐项校验并写入，成功后通过显式完成接口确认。手机可以在上传或下载前取消任务，会话空闲 90 秒后任务和临时文件由后台清理，节点启动时会清理上次遗留目录。传输内容和项目数没有固定业务上限，暂存空间受实际磁盘容量约束。
- **传输失败。** 接收端遇到同名文件时拒绝写入，文件校验失败时任务标记为失败。桌面和手机上传临时文件均登记在节点数据目录或手机暂存目录，异常退出后由下次启动清理遗留登记。手机多文件上传按已完成项目自动重试，连续失败后标记为失败并清理临时目录；活动传输长时间没有进展也会自动失败并清理。全部文件下载后任务进入 `completed`。目标暂时离线时，发送端重试查询进度。

## 硬件监控

首次启动默认在主显示器右下角显示紧凑的半透明本机硬件监控悬浮条，分两行显示 CPU、GPU、上传速率与内存、显存、下载速率。悬浮条不显示品牌或关闭按钮，未锁定时可以拖动，右键菜单可锁定或隐藏悬浮条；位置会保存并在下次启动恢复。锁定后悬浮条忽略鼠标事件并允许点击穿透，解锁入口是主窗口「本机硬件」面板的「解锁悬浮条」和托盘的锁定开关。托盘的「显示悬浮监控条」和「隐藏悬浮监控条」是同一个开关，按当前可见状态切换文案，选择会保存并在下次启动恢复。隐藏主窗口时，已显示的悬浮条仍可见。隐藏悬浮条后，后台采集、托盘摘要和局域网指标共享仍会继续。

在线设备行右侧显示对端的 CPU、内存、GPU 和上下行速率摘要。点击该摘要可查看逐 GPU 利用率、显存和更新时间。远端快照过期时摘要显示「指标已过期」，GPU 和显存能否读取取决于平台及驱动。

## 使用边界

- **网络信任。** 节点服务面向受信任网络，可达设备无需账号或配对即可访问共享内容。服务只绑定回环、私网、链路本地和 Tailscale 组网地址，并只公布成功监听且仍有效的地址；手动连接也限制在这些地址，公网地址不会被监听或放入二维码。
- **数据保留。** 每台机器独立持久化剪贴板历史和当前快照；历史按配置的条数或天数淘汰，相同内容只保留一条，文字和 PNG 图片单项均不超过 16 MiB，暂不设置额外总容量上限。历史不会通过节点间 WebSocket 批量同步。硬件指标只保留最新快照，传输任务状态随节点运行保存在内存。发送端的文件内容仍由窗口选出的 `File` 对象提供，窗口关闭前未上传完的文件需要重新选择。手机暂存文件在项目完成、取消、失败或会话过期后清理。
- **Wayland 桌面。** 系统剪贴板优先使用合成器提供的原生 data-control 协议，没有该协议时回退到 XWayland；两条通道都不可用时，桌面界面会显示原因并持续重试。此时在「共享剪贴板」中输入文字仍会写入 MeshShare 历史并广播给其他节点，只是无法写入本机系统剪贴板。Wayland 下悬浮监控条仍可显示和拖动，但全局坐标、强制置顶和点击穿透由合成器决定，不作为强保证。
