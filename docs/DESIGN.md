# MeshShare 产品设计

## 体验目标

桌面程序常驻运行，让用户在不同系统的电脑之间继续使用刚复制的内容。手机和平板通过浏览器临时加入，由用户主动操作剪贴板。传文件时，收发两端同时在线，保存位置由接收方决定。

## 桌面端

主窗口显示当前节点和在线设备。设备卡片显示设备名、平台、地址和硬件摘要，连接断开后对应设备从在线列表移除。关闭主窗口只隐藏窗口，托盘的「退出程序」会停止节点。

「共享剪贴板」显示最新的文字或图片。桌面采集的图片编码为 PNG，单张上限为 16 MiB。桌面复制后自动发布，也可以编辑文字并选择「立即同步当前文字」。暂停同步会阻止本机采集和主动发布，其他节点仍可更新本机剪贴板。

自动发现依赖局域网组播。主窗口提供「手动输入节点地址」，HTTP 查询成功后会启动带心跳和重试的 WebSocket 连接。

## 手机和平板网页

桌面端的「手机扫码访问」会列出本机的网络地址，包括可用的局域网地址和 Tailscale 地址。选择移动设备能访问的地址后，二维码随之更新。移动设备扫码打开网页即可使用。

网页显示连接的桌面节点、在线设备和最新共享文字。用户可以编辑文字并点「同步到设备」。系统剪贴板按钮需要浏览器权限和安全上下文，默认 HTTP 页面可通过文本框手动复制粘贴。[Clipboard API 规范](https://w3c.github.io/clipboard-apis/#async-clipboard-api)

## 文件直传

桌面流程设计为从目标设备卡片选择文件或文件夹，也可将项目拖到卡片上。接收端在「传输任务」中选择「接收」或「拒绝」，接受后选择保存目录。文件内容由发送方直接上传到接收端。

移动网页提供向其他在线桌面节点发送文件和文件夹的入口，也会把扫码连接的桌面节点列为目标。扫码后手机会建立临时接收会话；桌面端可在本机的移动设备卡片中发送文件，手机确认后逐项下载。浏览器需要能直接访问扫码节点。

当前使用限制如下。

- **桌面接收确认。** 收件任务由 Rust 运行时保留，界面通过 WebSocket 或 `GET /api/v1/transfers` 恢复；接收目录由本机 Tauri 文件选择器确认。
- **手机在默认 HTTP 页面发文件。** 手机网页使用分块 SHA-256 实现和 `File.stream()`，不依赖 Web Crypto 安全上下文，也不会一次性读取整个文件。
- **手机接收文件。** 手机接收会话只在扫码节点上有效，文件由该节点临时保存并通过 HTTP 流下载；会话空闲 90 秒后任务和临时文件由后台清理，节点启动时会清理上次遗留目录，每个会话的临时清单总量上限为 5 GiB。
- **传输失败。** 接收端遇到同名文件时拒绝写入，文件校验失败时任务标记为失败。目标暂时离线时，发送端重试查询进度。已经完成的文件保留在接收目录中。

## 硬件监控

首次启动默认显示本机硬件监控悬浮条。应用记住用户在托盘选择的显示模式。隐藏主窗口时，已启用的悬浮条仍可见。选择「监控模式：仅托盘」或「关闭硬件监控」都会隐藏悬浮条，后台采集、托盘摘要和局域网指标共享仍会继续。

在线设备卡片显示对端的 CPU、内存和网络摘要。点击「查看监控」可查看逐 GPU 利用率、显存和更新时间。远端快照过期时显示「指标已过期」，GPU 和显存能否读取取决于平台及驱动。

## 使用边界

- **网络信任。** 节点服务面向受信任网络，可达设备无需账号或配对即可访问共享内容。服务只绑定回环、私网、链路本地和 Tailscale 组网地址，并只公布成功监听的地址；公网地址不会被监听或放入二维码。
- **数据保留。** 共享剪贴板和硬件指标各自只保留最新快照，传输任务状态随节点运行保存在内存。发送端的文件内容仍由窗口选出的 `File` 对象提供，窗口关闭前未上传完的文件需要重新选择。手机临时文件随接收会话过期清理，并受每会话 5 GiB 配额限制。
- **Ubuntu Wayland。** 系统剪贴板同步依赖 XWayland 和桌面环境的剪贴板桥接。自动读取不可用时，可尝试在「共享剪贴板」中输入文字并主动同步。当前节点无法写入系统剪贴板时，主动同步也会报错。
