# MeshShare 产品设计

## 使用场景

用户在一台设备执行启动命令，把终端显示的局域网地址发给同一网络中的其他设备。所有设备打开同一个页面后看到共享板：最新剪贴板、短消息时间线和文件列表。任何设备都可以发布文本、上传文件或复制剪贴板内容；其他打开页面的设备会在几秒内看到更新。

桌面用户直接运行独立程序即可：原生 GUI 负责启动服务、展示局域网地址，并在窗口内提供共享剪贴板、消息和文件操作。手机和平板不需要安装桌面程序，只需用浏览器访问该地址。

共享板适合临时传链接、代码片段、截图和小文件。它不提供账号、跨网络同步或离线编辑，也不把局域网共享误认为长期云盘。

## 交互原则

- 首屏显示在线状态；连接失败时保留已知内容，SSE 会自动重连并重建状态。
- 发布消息由服务端确认后进入时间线；失败时保留编辑内容并显示错误，避免静默丢失。
- 文件上传显示进度、大小和失败原因；下载使用原始文件名，删除需要二次确认。
- 剪贴板是“最近一次共享值”，发布时明确显示来源设备和时间；浏览器的系统剪贴板权限只在用户点击复制时请求。
- 所有用户可见文本按纯文本显示，链接由用户主动点击；不执行共享内容中的脚本。

## 默认限制

默认消息长度 10,000 个 Unicode 字符，单文件 100 MiB，文件名最多 255 个字符，保存最近 500 条消息。限制可通过启动参数调整，但不能设置为无限。超过限制时 API 返回明确的 `413` 和可读错误码，客户端保留编辑内容。

## 故障表现

服务端不可达：顶部变为离线，客户端指数退避重试；本地草稿不丢失。SSE 断开：先继续轮询状态，恢复后从最新 revision 重建视图。磁盘不足或权限错误：写入操作失败并显示服务端错误，已有内容仍可读。其他客户端删除内容后，当前页面下一次同步移除该条目。

## 验收标准

启动后可从另一台局域网设备打开页面；两个浏览器同时打开时，任一端发布消息，另一端在一次同步周期内可见；上传文件后可从另一端下载且内容校验一致；重启服务后消息、剪贴板和文件元数据仍存在；服务端不把正文写入请求日志；超限和非法路径请求得到 4xx 而非进程崩溃。
